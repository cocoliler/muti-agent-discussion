# 团队分工
| 成员 | 当前任务 | 模块接口与交付 | 后续P2 |
|---|---|---|---|
| A 架构契约 | T01 Schema、规划参数、契约生成规则 | 字段/错误/版本评审；设计基线owner | 运行契约和技术实验 |
| B 前端（用户） | T03规格入口、T06任务/画布、T07保存冲突前端 | 只用DTO和REST；不实现后端调度 | 运行监控与成果界面 |
| C PM Agent | T04 Provider、Prompt、结构化修复 | 输入SpecRevision，输出TaskProposal/诊断 | 多角色执行和审查 |
| D 编排 | T05校验、Kahn、批次与阶段 | 纯函数，统一Issue；不调用模型 | 调度和状态机 |
| E 后端数据 | T02项目/规格、T07计划版本/API | 事务、CAS、幂等、Windows启动 | Artifact/事件/审批持久化 |
| F 测试交付 | T08通用验证、变异、端到端与证据 | 不代替模块单测；REAL与TEST分开报告 | 故障恢复与质量评审 |

依赖：A先定契约；B/C/D/E可按同一契约开发；C候选经D验证，E协调落库，B投影，F闭环验证。
3–5人兼任方法见Git规范，不能因为人数变化把B分配为编排算法owner。
