# 产品需求文档
## 核心旅程
用户在工作台创建项目 → 填写/导入规格 → 修正校验问题 → 确认可选规划参数 → 生成开发计划 → 查看需求覆盖和编排 → 调整任务/依赖 → 校验保存新版 → 导出或打开历史。
未来在已确认版本上启动执行 → 查看成果和失败原因 → 人工审批 → 验证 → 反馈到新规格/计划。

## 主要交互
项目页使用“规格 / 计划”两项主导航；计划内部“任务列表 / 工作流”，校验为可定位的抽屉，历史为版本选择器，避免六个空页面。
规格入口为紧凑按钮及摘要，不让大文本区挤占画布。首次无规格时直接展示表单。
主操作随上下文显示“生成计划”“重新编排”“保存版本”；当前阶段不显示“运行成功”等执行语义。
模型生成期间规格可以另存新版，但当前请求仍绑定原版本；到达结果注明“来自规格 vN”，不得覆盖当前未保存编辑。

## 可配置与限制
P0 直接基于输入规格规划，不要求选择模板；只提供模型、粒度和可选角色/规则约束。
预设流程模板、模板库和模板编辑器均后置，本轮不补充。
所有关键业务需求有稳定 ID。遗漏关键输入阻止规划；非关键假设展示并在正式保存时确认。
预算、超时和失败都有确定错误；REAL 失败不自动切换 TEST。

## 成果与验收
输出规格快照、候选任务、依赖、拓扑批次、覆盖报告、计划版本和可视化；JSON 是可交换计划，PNG 是展示辅助。
详细逐条需求只在 [SRS](REQUIREMENTS.md) 维护；设计与测试映射只在 [追踪矩阵](REQUIREMENTS_TRACEABILITY.md) 维护。
