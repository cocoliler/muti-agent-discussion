# 软件需求规格说明书（SRS）
版本 v3.1；本文“必须”指对应优先级的交付要求，非已实现声明。
每项输入/输出采用领域契约，验收编号在追踪矩阵连接到具体测试。

| ID / 优先级 | 业务价值与场景 | 输入 → 输出 | 模块 / 约束 | 验收 |
|---|---|---|---|---|
| R01 P0 | 团队切换不同产品 | 项目名称 → Project | Project；本地单用户，归档不物理删除历史 | A01 两项目隔离 |
| R02 P0 | 有依据地规划 | 表单/JSON/补充文字 → SpecRevision | Spec；严格字段、稳定需求 ID，最多 1 MiB | A02 导入导出一致 |
| R03 P0 | 避免缺失与编造 | 规格 → ValidationReport | Spec；缺必填阻断，语义问题提示人工，不能声称识别全部矛盾 | A03 不完整规格不调用模型 |
| R04 P0 | 不同产品真实规划 | 规格版本+可选参数 → PlanningRun/TaskProposal | PM；REAL 模型、TEST 明示，最多三次调用 | A04 真实规格规划 |
| R05 P0 | 可追踪交付责任 | 候选任务 → 带角色/交付/验收/需求引用任务 | Decomposition；角色非运行实例，估算可空 | A05 引用与字段完整 |
| R06 P0 | 确保可执行的依赖结构 | tasks → 编排/诊断 | Validation；唯一性、存在性、自环、环、输入输出引用 | A06 无效图拒绝 |
| R07 P0 | 解释顺序与并行 | 合法 DAG → batches/order/stages | Orchestration；拓扑层与业务阶段不同，布局不影响次序 | A07 菱形汇合正确 |
| R08 P0 | 查看与理解计划 | PlanRevision → 列表/画布/详情 | Visualization；task_id 同源，计划状态不伪装执行状态 | A08 图表一致 |
| R09 P0 | 人工纠偏 | 任务/依赖修改 → 校验后新版本 | Editor；CAS 冲突；不覆盖历史 | A09 编辑与旧版共存 |
| R10 P0 | 本地可恢复成果 | 计划/布局 → DB/JSON/历史 | Persistence；无模型也可用，TEST 来源保留 | A10 重启恢复 |
| R11 P0 | 验证通用性和定制 | 不同规格、规划粒度 → 不同结果 | PM/Testing；不得产品名分支或固定业务任务表 | A11 变异测试与人工评审 |
| R12 P0 | 可理解地恢复失败 | 超时/429/非法 JSON → 诊断和重试入口 | Provider；不无限重试、不静默降级 | A12 故障注入 |
| R13 P1 | 编辑效率 | 操作序列 → 撤销/重做/分组折叠 | Editor；仅草稿，不能撤销历史执行 | A13 操作可逆 |
| R14 P1 | 过程定制便捷 | 规划参数 → 配置快照 | PlanningPolicy；不可执行脚本，修改不影响旧计划 | A14 约束冲突阻断 |
| R15 P2 | 真正完成开发活动 | 已确认计划+角色映射 → Run/Artifact | Execution；沙箱/工具能力明确后才执行 | A15 真实交付物与依赖 |
| R16 P2 | 人机协同与质量 | Run/成果 → 审批/审查/修订 | Monitoring/Verification；失败不可被 LLM 自评覆盖 | A16 审批与修订证据 |
| R17 P2 | 扩展输入 | Markdown/文档 → 待确认规格 | Spec；解析不能无提示补造 | A17 缺信息标注 |
| R18 Out of Scope | 云级协作 | 多租户/实时共同编辑 | 无当前接口和实施任务 | 检查无此承诺 |

## 最终产品业务规则
任务生命周期分成规划对象和执行对象；计划合法不等于成果合格。人工确认绑定具体版本及 hash。
未来 Agent 按角色能力注册，工具受限，输出必须归档；监督不直接修改被冻结的运行计划。
质量目标（Q01–Q08）由 [质量属性](../testing/QUALITY_ATTRIBUTES.md) 量化。当前阶段不承诺自动产出可部署整套软件。
