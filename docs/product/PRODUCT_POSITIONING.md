# 产品愿景与定位
## 正式定位
**FlowStudio：通用可定制的智能软件工程工作流平台**。
英文：Configurable AI-Powered Software Engineering Workflow Platform。

平台以软件产品 Design Spec 为输入，结合可选的规划参数，通过 AI Agent 进行任务规划，以确定性规则组织依赖，逐步连接多 Agent 执行、人工干预与结果验证。软件案例是输入数据；平台不包含“微信”“小红书”等产品名分支判断。

## 用户与价值
| 用户 | 实际问题 | 产品价值 |
|---|---|---|
| 软件工程学生与教师 | 任务分解不可追踪、流程只画图 | 展示输入需求、规划依据、依赖和验证证据 |
| 小型研发团队 | 职责不清、遗漏验收、计划难调整 | 统一规格版本、交付物和可编辑计划 |
| 流程设计者 | 每个项目重新搭流程 | 配置阶段、角色、规则和规划粒度，复用过程而非业务任务 |

## 生命周期
需求与规格管理 → 开发任务规划 → 流程编排 → 任务执行 → 执行监控 → 结果验证 → 反馈与改进。
课堂作业 2 接受已有设计规格，只落地至编排可视化；不要求重新自动编写 PRD 或产出完整软件代码。

## 产品边界
面向软件工程、相对通用、合理可配置、Agent 驱动、工作流中心、可视化、可扩展、Local-First。
配置限于版本化数据：阶段、角色、任务类别、Prompt、粒度、验证规则。当前不支持运行任意插件脚本。
不做聊天机器人、固定项目生成器、通用互联网自动化平台或多租户 SaaS。
Local-First 指本地项目、规格、计划和历史可离线读取编辑；REAL 规划需要外部模型。TEST 必须有明确来源标识。

## 成功判断
同一代码读取不同产品的用户规格，产出与需求相匹配的不同任务及依赖；人可解释、可修改、可验证、可恢复。
最终项目再验证计划与实际成果、审查证据及修订之间的一致性。不得以节点数量、页面数量或 Agent 数量衡量质量。
