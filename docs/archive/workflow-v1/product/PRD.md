# 产品需求文档

设计稿 1.0 · 2026-11-14。产品边界见 [愿景](PRODUCT_VISION.md)，精确技术要求见 [SRS](SRS.md)，优先级见 [FEATURE_PRIORITY](FEATURE_PRIORITY.md)。

## 核心对象与用户语言

一个项目组织多条工作流。工作流拥有一个可修改草稿，草稿内包含规格、任务、可执行定义和画布布局；发布产生不可变版本。一次“运行”是特定快照与输入的执行记录。运行历史不是当前草稿的状态，也不是一次前端动画。

界面使用“草稿测试”“发布版本”“运行版本”“重新运行”四个不同动作。“发布”仅意味着冻结可复用版本，不意味着上传到云端或开启外部触发。“重新运行”创建新记录，不覆写失败记录。

## A. 工作空间、项目与工作流

本地仅一个应用工作空间，无注册登录。工作台展示最近编辑、待审批、最近失败和创建入口，所有数量从服务端查询，不能放示例数字冒充统计。项目列表支持名称搜索、更新时间排序和分页；项目名称 1～80 字，描述最多 2,000 字。

创建项目后进入项目详情；创建工作流得到含 Start/End 的未完成草稿，首次引导填写规格和任务。工作流名称 1～100 字；同项目内未删除工作流名称不重复。复制工作流若后续实施，属于 P1，不与 P0 节点复制混淆。

项目和工作流删除采用软删除；确认框显示影响的工作流数量和历史保留策略。存在未终态运行时拒绝删除并给出监控入口。已删除对象不可新建运行，其历史仍可查；物理清理由数据维护策略控制。

## B. 规格管理

规格包含业务目标、任务描述、输入要求、输出要求、处理规则、验收标准和异常处理。输入输出使用可编辑 JSON schema 子集，并提供简易字段表单；首版支持 object/array/string/number/boolean/null 和必要约束，不承诺支持全部 JSON Schema 语义。

验收标准分成文字说明与可执行断言：文字说明供人审查，可执行断言由白名单比较器表达并可映射 Assert/TestCase。禁止仅凭“运行成功”自动把所有文字验收标准标为通过。规格修改和图修改共用 draft revision；历史版本保存当时规格，避免验收依据漂移。

## C. 任务分解

用户手动增加 TaskItem，填写标题、职责、依赖任务、输入输出和完成条件。任务本身是规划对象，未映射时显示“待编排”。选择任务可以在画布创建节点或关联现有节点；一个任务可映射多节点，一个节点至多关联一个任务。

任务依赖必须由控制图中的路径解释；任务依赖循环、跨工作流关联和引用不存在的节点均错误。节点类型及端口定义决定执行行为，任务描述不被解释执行。任务完成状态从该运行的关联 NodeRun 汇总：全部成功或合法跳过且该任务被激活才可称完成；整个任务未激活显示“未执行”，不能算业务已完成。含失败/取消/中断时明确呈现该结果。

## D. 画布编排

左侧节点库按输入输出、处理、控制、人工、验证分组，支持搜索与点击添加/拖入。中央画布提供节点拖动、连线、断线、框选、复制粘贴、删除、缩放、平移、适配视图、撤销重做和自动布局。分组只是视觉容器，P0 不嵌套、不执行。

单击节点打开右侧属性；连线前即时检查端口和方向，提交时再检查循环和类型；服务器校验为最终权威。复制时生成新 ID、重映射被复制集合内部的引用与边；对集合外引用显示仍指向原节点的提示。删除被引用节点展示影响清单，确认后保留明确的引用错误，不静默改为 null。

一次拖动算一次撤销记录，自动布局可整体撤销。文本框内快捷键优先作用于文本，不能误删节点。未保存、保存中、已保存、失败、冲突都能在顶部区分。布局不能影响执行顺序；更详细行为由 [编辑器设计](../design/WORKFLOW_EDITOR_DESIGN.md) 定义。

## E. 校验与发布

校验结果按 error/warning 分类，包含 code、message、nodeId/edgeId、fieldPath 与修复建议。点击问题定位图和字段。阻塞错误禁止发布和运行；未关联任务等规划问题的等级由 SRS 定义。

发布前等待所有编辑和表单提交、保存成功、校验通过；请求必须携带当前 revision。版本冻结规格、任务、定义和 layout，记录版本号与说明。重复提交通过幂等键返回原结果。运行中的草稿可继续编辑，但运行视图锁定自己的快照。

## F. 执行与人工交互

P0 提供九种节点，见 [节点目录](FEATURE_PRIORITY.md)。全局最多同时执行 4 个节点，每 run 2 个；接纳 2 个未终态运行，排队最多 20。审批等待仍占 run 名额但不占节点槽；界面解释排队原因并支持取消。

Join 等所有入边得到 ACTIVE/INACTIVE；无激活输入则跳过，有激活输入才执行。任何最终失败触发整次运行停止派发并收敛失败；普通跳过不等于失败。运行只有 End 成功、必要断言通过且所有节点终态才成功。

审批卡展示任务、所需决定、截至时间与相关输入；用户批准或拒绝，重复点击不会重复推进。批准激活下游，拒绝导致失败。浏览器关闭不会自动批准或取消；服务重启则本次运行中断，不能继续审批旧记录。首版不提供任意时刻暂停按钮。

## G. 监控与历史

监控画布使用真实 NodeRun 和边状态，显示运行中、成功、失败、等待审批、跳过、取消、中断；图标/文字辅助颜色。节点详情显示输入、输出、时间、每次 attempt、错误及相关事件。耗时来自后端时间戳；前端可显示进行中计时，但不能推算成功状态。

SSE 断线时显示“连接中断，运行可能仍继续”，保留最后确认状态；恢复后按序补发或重新读取快照。历史按工作流、状态、时间筛选；点开历史时展现当时版本，链接当前草稿时提示二者可能不同。输出过大时使用明确限额错误，不截断后声称结果完整。

## H. 执行验证

静态校验检验“能否执行”；节点测试检验执行器在指定输入下的结果；流程测试检验跨节点行为；Assert/TestCase 检验结果是否符合业务预期。四层结果分开显示。

单节点测试只使用明确输入 fixture，不偷偷执行上游；控制节点通过小图流程用例验证，不给单节点测试按钮制造无意义结果。测试运行同样有持久记录，标识来源 TEST；预期值与比较器冻结，不能事后修改预期使历史变绿。比较结果包含 JSON Pointer、期望值、实际值和差异原因。

## 标准验收演示与异常路径

| 情境 | 用户观察 | 业务结论 |
|---|---|---|
| 普通订单通过 | 高额审批支路跳过，Join 正常继续，最终断言通过 | 无需人工仍可完整离线执行 |
| 高额订单批准 | 审批持久等待，刷新仍显示；批准后继续 | 人工决定真实控制执行 |
| 审批拒绝 | Approval 失败，下游停止，保留决定 | 拒绝不能伪装成成功 |
| 断言不符 | 输出存在但 Assert 失败，差异可定位 | 执行完成不等于验证通过 |
| 运行中修改草稿 | 运行仍显示旧快照，草稿出现未发布修改 | 行为可复现 |
| 断网/关闭浏览器 | 本地服务继续；重连补发状态 | UI 不是执行引擎 |
| 杀掉服务后重启 | 未完成运行标记 INTERRUPTED，可新建重跑 | 不承诺自动故障续跑 |

## 需要在实施中验证的产品假设

200 节点是否覆盖典型演示、审批等待是否经常需要跨服务重启、用户是否接受 P0 纯本地处理，均为需要使用反馈验证的假设。当前推荐保持基线，先用标准场景证明闭环；若需要外部 API，优先开发 P1 HTTP GET，而非扩大到任意脚本。
