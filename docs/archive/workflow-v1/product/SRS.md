# 软件需求规格说明

设计稿 1.0 · 2026-11-14。以下均为待实现、待测试的要求。需求 ID 用于开发任务和验收报告追踪，语义以 [BASELINE](../BASELINE.md) 及 [引擎设计](../architecture/WORKFLOW_ENGINE_DESIGN.md) 为准。

## 功能要求

| ID | 必须行为 | 可观察验收条件 |
|---|---|---|
| FR-01 | 管理本地项目：创建、编辑、列表、搜索、软删除 | 创建后重启仍存在；搜索不串项目；有未终态运行时删除返回明确冲突 |
| FR-02 | 管理项目内工作流与历史入口 | 同项目未删除名称不重复；软删除后不能运行；已存历史仍可查询 |
| FR-03 | 保存结构化规格及验收说明 | 七类字段可编辑；输入输出 schema 校验；发布后改规格不改变旧版本 |
| FR-04 | 手动 TaskItem 拆解、依赖和节点关联 | 拒绝任务环与跨工作流引用；一个节点至多一个任务；依赖在图路径中不可解释时禁止发布 |
| FR-05 | 完整基础画布与效率操作 | 添加/删除/拖动/连接/断线/分组/复制/多选/缩放/平移/撤销重做/布局均可操作并可恢复；分组不改变执行 |
| FR-06 | 草稿保存、恢复与并发冲突 | 所有草稿内容共用 revision；旧 revision 写入返回 409，不能静默覆盖；页面刷新得到最后确认保存内容 |
| FR-07 | 服务端权威静态校验 | 无配置/断端口/不可达/环/类型错/无效引用/非法分支均定位到图或字段；发布和运行复用同一规则 |
| FR-08 | 不可变版本与运行快照 | 发布事务读取一致 revision；草稿测试先保存再冻结；运行不读取活动草稿；历史显示快照 layout |
| FR-09 | 真正执行有向无环图 | 顺序、条件、Parallel、Join 按定义产出实际 JSON；无前端页面也执行；跳过分支不阻塞 Join |
| FR-10 | 有限并发、取消、重试和超时 | 达到节点并发上限时排队；重试总尝试最多 3；取消 5s 内收敛且晚到结果不能覆写终态 |
| FR-11 | 持久审批点 | 创建 ApprovalRequest 并释放节点槽；批准一次推进一次；拒绝失败；过期不可批准；重启撤销未决请求 |
| FR-12 | HTTP 命令 + SSE 事件同步 | 状态和事件同事务；runId+seq 单调且可去重；断线重连得到缺失事件或重新读取快照；断线不取消 |
| FR-13 | 查询运行/节点/attempt 历史与事件 | 显示版本、来源、输入输出、时间、错误和尝试；按游标分页；历史内容不可被草稿编辑修改 |
| FR-14 | 静态、节点、流程和结果验证 | Transform/Template/Assert 可输入 fixture 真测；控制节点由小图测试；预期/实际差异持久化；断言失败不可成功 |
| FR-15 | 明确处理中断与重跑 | 服务重启扫描全部未终态运行和节点，标 INTERRUPTED；保留已完成输出；重跑产生新 runId 并关联原记录 |
| FR-16 | 本地设置、备份、清理与诊断 | 数据目录可配置；一致备份可恢复；清理仅终态且不破坏引用；设置不存在不生效的虚假按钮 |
| FR-17 | 统一节点描述/执行契约 | 九种内置节点注册可验证；前端读取序列化描述，后端按 type+version 解析执行器；未知类型阻止发布/运行 |

## 静态校验级别

| 错误类别 | 等级 | 规则/修复方向 |
|---|---|---|
| Start/End 数量、环、不可达、无法到达 End | error | 单 Start/End；使用拓扑排序和前后向遍历，移除环或补齐控制路径 |
| 普通节点多控制入边、缺少分支、重复端口 | error | 显式 Join 多入边，Condition 必有 true/false，校验注册端口 |
| 配置或输出声明无效 | error | 校验配置 schema 和受支持 JSON schema 子集，不接受未知字段悄然失效 |
| 必需引用来自非支配节点 | error | 增加控制依赖，或改为可选引用+fallback，或经 Join activeInputs 处理 |
| 类型、JSON Pointer、节点 ID 无效 | error | 定位属性路径；结构化选择替代字符串猜测 |
| TaskItem 环、依赖无图路径、节点关联不存在任务 | error | 修正任务依赖/节点关联，并重新检查映射 |
| 任务未关联任何执行节点、未填写文字验收说明 | warning | 草稿可试验，发布前显示并要求用户了解未覆盖部分；不把未覆盖标为完成 |

测试运行中的 fixture 输入仍须通过 schema，不以“调试”跳过输入验证。服务端运行时再次校验实际输出类型与大小；静态通过不保证执行器没有错误。

## 非功能要求

| ID | 要求与阈值 | 验证方式 |
|---|---|---|
| NFR-01 本地兼容 | Windows 10/11 x64、Node 24 LTS；无需数据库服务/中间件；首次依赖安装后基础功能离线 | 干净 Windows 冒烟；断网执行标准流程；better-sqlite3 安装兼容性作为实施门槛 |
| NFR-02 数据一致性 | SQLite 本机磁盘，状态+事件短事务；无事务内 await；版本快照不可变；重复命令幂等 | 事务故障注入、重复请求和重启测试；SQLite 外键/检查约束检查 |
| NFR-03 容量与性能 | 200 执行节点/400 边/20 组；输入输出各 1 MiB/节点；定义请求 2 MiB；10,000 事件/run；拖动≥30fps；保存/状态可见 p95<500ms | Windows 4 核/16GB/SSD/稳定 Chromium，固定测试图和数据；记录版本、样本量、分位数和异常，不能只报告均值 |
| NFR-04 可访问性 | 状态不只依赖颜色；关键流程键盘可完成；可见焦点、正确标签、支持减少动效；正文对比目标≥4.5:1 | 键盘走查+自动检查+节点连接替代操作；1366×768/1920×1080 检查遮挡 |
| NFR-05 安全边界 | 只监听 loopback；限制 Origin/Host 与请求体；不执行任意 JS/Shell；敏感字段脱敏，导出不包含机器秘密 | 跨源命令拒绝、超限载荷、路径边界、日志脱敏测试；线程不作为安全沙箱 |
| NFR-06 可维护性 | contracts 独立、引擎无 React/HTTP/ORM 依赖；节点注册和执行可单测；迁移可追踪 | 依赖规则/类型检查、契约测试、迁移评审、本地检查命令 |
| NFR-07 可观察性 | requestId/runId/nodeRunId/attempt 关联；错误有稳定 code 与可操作消息；历史分页/日志限额 | 注入配置/执行/磁盘/数据库错误，检查 UI 和日志能关联且不泄漏秘密 |
| NFR-08 恢复与资源 | 重启未终态统一中断；队列20、接纳run2、全局节点4、每run2；事件上限前保留终态提交容量 | 杀进程后重启、审批长等、并发压力、事件限额与清理边界测试 |

性能指标必须在实现后验证。若不达标先测量节点渲染、JSON 大小、事务耗时，再调整实现或经评审修订指标；不直接添加 Redis/分布式服务。

## 接口与输入约束

API 使用 JSON，时间为 UTC 毫秒整数，ID 为 UUID 字符串，枚举采用 BASELINE 中大写状态。所有写请求校验 body 和目标对象归属；保存使用 revision，发布/运行/审批/取消使用幂等机制。错误提供 code、message、requestId 和可选 details/fieldPath；HTTP 状态与错误类别不得矛盾。详见 [API](../architecture/API_DESIGN.md)。

首版不保证任意 JSON Schema 互相兼容的静态证明，只支持声明的子集并对运行数据做完整子集校验。无法证明的引用应要求更明确配置，不能默认“任何类型都可连接”。

## 跟踪与验收

每个开发任务应至少引用一个 FR/NFR；测试报告应记录输入、预期、实际和证据。总体验收以 [验收标准](../development/ACCEPTANCE_CRITERIA.md) 为入口，不能仅以文档存在、页面可点击或动画完成判定系统通过。
