# 测试与质量策略

本文件定义待实现测试；本轮只做文档审查，没有应用可测试，未获得任何测试通过或性能达标结论。状态、并发和限额均遵循 [设计基线](../BASELINE.md)，完成条件见 [验收清单](ACCEPTANCE_CRITERIA.md)。

## 工具与分层

采用 Vitest 做纯逻辑/组件测试，Fastify inject + 真实临时 SQLite 做 API/事务集成，Playwright 做 Chromium 端到端。执行时钟、ID、executor、repository 通过依赖注入；单元测试可控时间而不长时间 sleep，集成测试保留真实事务与文件。不要用内存 mock 数据库来证明 SQLite 外键、唯一约束、并发和迁移正确。

|层级|必测对象|不替代什么|
|---|---|---|
|契约|Schema、定义decode、错误格式、版本拒绝、事件序列|不能替代实际API传输|
|纯核心|拓扑、支配关系、边状态传播、输入绑定、计划确定性|不能证明持久提交正确|
|执行器|白名单运算、模板、条件、断言、大小/类型边界|不能用执行器成功证明run成功|
|集成|运行/节点/attempt/event原子提交、保存冲突、审批/取消竞态|不能代替浏览器反馈|
|E2E|完整业务流程、键盘操作、真实SSE与历史|不对每个CSS像素写脆弱测试|
|故障/性能|进程崩溃、DB失败、断流、资源上限、200节点|不能从小fixture推断大规模吞吐|

## 统一离线验收夹具

`packages/test-fixtures` 保存版本化 JSON、规格、任务、输入、测试断言和期望路径。建议标准案例“采购金额复核”：Start输入 `{amount:1200,owner:"  Li  "}` → Transform修剪owner → Condition `amount > 1000`。true经Approval后进入Join，false直接到Join；Join后Parallel分别Template生成摘要和Transform计算数值，再Join→Assert→End。另设无审批输入 `{amount:100}`。该案例只处理内存 JSON、字符串和人工决定，完整闭环不需外网、文件写入或第三方 API。

由fixture显式绑定 Join.activeInputs，不能假设未激活分支产生值。每个fixture给出定义hash、期望节点终态、active/inactive边、End输出及事件关键顺序。测试不能只断言“页面出现成功”。测试专用延迟/错误executor只在测试registry注册，不出现在产品节点目录。

## 调度与状态机矩阵

|ID|输入或注入点|必须观察的结果|
|---|---|---|
|ENG-01|串行3节点|上游输出先提交后下游READY；最终输出精确匹配|
|ENG-02|Condition true和false两组|仅选中出口ACTIVE，未选路径SKIPPED；Join等所有入边resolved后只执行一次|
|ENG-03|嵌套条件使Join全部输入INACTIVE|Join及后续失活路径SKIPPED，不永久PENDING|
|ENG-04|Parallel快/慢两条支路|Join等待慢支路；activeInputs按边ID排序，不随完成先后变化|
|ENG-05|并行一路最终失败、另一路慢返回|fail-fast关闭新调度，取消同伴；5s内FAILED；晚成功不改终态|
|ENG-06|同一READY节点被两次wake/扫描|条件认领与唯一attempt约束仅执行一次|
|ENG-07|纯计算可重试错误两次后成功|尝试1/2/3分开记录，1s/2s退避；等待不占执行槽|
|ENG-08|不可重试错误或effect external|不自动重试，默认总尝试1；没有伪造exactly-once|
|ENG-09|超时后旧attempt回调|token失效，旧输出不得覆盖新attempt或终态|
|ENG-10|取消与成功同时竞争|按事务先后确定唯一结果；CANCELLING后新调度为零；generation拒绝晚到结果|
|ENG-11|Approval同意/拒绝/截止过期|同意一次推进；拒绝或过期失败；重复决定不能推进两次|
|ENG-12|审批与另一条执行/重试支路并存|run维持RUNNING，只有剩余均审批等待才WAITING_APPROVAL|
|ENG-13|2个已接纳run和20个排队上限|审批仍占接纳名额，节点槽全局≤4、每run≤2；超限请求明确失败|
|ENG-14|仍有unresolved但无可运行/等待/计时|ENGINE_DEADLOCK终止，报告相关节点而不无限空转|
|ENG-15|End成功但断言失败或其他激活节点未终结|run不得SUCCEEDED|
|ENG-16|必需引用指向不支配目标的条件分支|静态校验拒绝；optional+fallback或Join后合法绑定可通过|

还需生成小型随机DAG（固定随机种子）检查不变量：终态不回退；每个有效attempt最多提交一次；每条边仅从UNRESOLVED变为一个终态；未激活节点不执行；所有已提交节点状态都有相应事件。此类性质测试覆盖组合风险，不以高测试数量为目标。

## 持久化、恢复与传输故障矩阵

|ID|故障注入|验收结果|
|---|---|---|
|DB-01|保存写到一半抛错|规格/任务/definition/layout和revision共同回滚|
|DB-02|两个标签同revision保存|只有一个成功，另一个409且保留本地内容|
|DB-03|发布与保存竞争|版本快照来自同一revision，无混合数据|
|DB-04|节点输出已算出、commit失败|不发送成功SSE、不调度下游；进入持久层不可用处理|
|DB-05|事件插入失败|状态输出一起回滚，不能出现无事件的成功状态|
|DB-06|服务在QUEUED/RUNNING/RETRY_WAIT/审批等待被强制终止|重启后对应未终态运行及节点INTERRUPTED，审批撤销，不自动执行；已完成结果保留|
|DB-07|外部副作用已发生但提交前崩溃（测试executor模拟）|只呈现中断且提醒重新运行可能重复；不声称回滚外部效果|
|DB-08|SQLITE_BUSY/FULL/IOERR|有界处理/明确失败，停止新调度；无法落盘时显示未确认，恢复重启后中断|
|DB-09|迁移中断与旧库升级|版本不伪进位；空库和旧fixture均可升级；失败不销毁原库|
|DB-10|服务仍运行时尝试备份恢复|维护锁拒绝；停止后备份恢复到新目录，通过完整性及业务读取|
|EVT-01|seq=N后断开，后端产生N+1…M|重连补齐，去重；断线没有取消run|
|EVT-02|补发历史与订阅live交接时新增事件|持久游标读取无缺口；前端按runId+seq幂等应用|
|EVT-03|重复、乱序或缺口事件|重复忽略；缺口触发补拉/快照，不能跳过直接显示完成|
|EVT-04|客户端游标超过服务端或历史已清理|按API约定重新取快照；不是无限重连旧游标|
|EVT-05|慢SSE客户端、10,000条事件边界|有界缓冲并可断流补发；不阻塞引擎/无限涨内存|

进程崩溃测试在独立临时目录和测试进程运行，精确控制退出点；不能杀用户实例。磁盘满使用注入的持久层错误及隔离环境验证，不填满用户磁盘。所有fixture不包含真实密钥与业务资料。

## 静态校验和编辑器测试

覆盖必填/类型/端口/重复ID/自环/环/不可达/无End路径/分支缺口/跨分支引用/未知节点版本/任务依赖不匹配；诊断必须含nodeId/fieldPath/code/fixHint。前端即时拒绝和后端发布拒绝共享fixture验证。保存允许结构合法但业务配置未完成的草稿，不能用发布级校验阻止用户保存半成品。

编辑器重点是业务不变量：拖动结束后仅一个历史命令；复制选择子图时内部引用重映射，外部引用保留且重新验证；删除节点清理边并给出引用问题；撤销恢复原ID；视觉组不改拓扑；自动布局可撤销；动态端口变更不遗留幽灵连线；Ctrl+Z在文本输入内不劫持浏览器文本撤销。

## 浏览器、离线与安全检查

Playwright使用真实server、真实临时DB、同源SSE，外网请求一律拦截；完成创建项目→规格任务→搭图→校验→保存发布→测试运行→审批→核对输出→刷新历史。另测保存冲突、服务离线、运行中切页面、日志定位、取消、错误提示键盘焦点和两种桌面尺寸。单节点测试限定Transform/Template/Condition/Assert，提供样本输入、不隐式执行上游。

本地安全检查包括非法Host/Origin/CSRF、文本输出XSS、模板注入、未知节点加载、超大JSON、递归深度、事件/日志超限、敏感字段脱敏。确认浏览器bundle没有执行器/数据库依赖、页面不请求CDN或遥测。P0未实现任意代码执行，因此不编造沙箱逃逸测试成果。

## 性能测量与发布记录

固定 Windows x64、4核、16GB RAM、SSD、当前稳定Chromium；记录具体CPU、OS、Node、SQLite、浏览器与提交ID。200节点/400边/20组，采样30秒拖动，目标≥30fps；保存API与提交事件到UI各至少100次，记录p50/p95/p99和失败数，目标p95<500ms。并发按4全局/2每run，负载不能偷偷降低。两次独立运行确认，不以单张截图宣称性能通过。

本地检查次序：格式/lint/typecheck → 纯核心 → 真实SQLite集成 → build → E2E → 指定故障与性能。通过后仅在改动或新风险影响时重跑相关检查。发布证据应含命令、退出码、环境、测试报告、失败复现和已知限制；未测项仍为未测，不能用设计审查代替。
