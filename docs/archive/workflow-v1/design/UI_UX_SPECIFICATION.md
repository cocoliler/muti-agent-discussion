# 页面 UI/UX 规格

页面结构见 [信息架构](INFORMATION_ARCHITECTURE.md)，视觉令牌见 [设计系统](DESIGN_SYSTEM.md)。八类页面共享搜索/分页/空态规范，但各自有明确业务职责。所有下述“数据”均指未来 API 服务端真实数据；离线原型是显式标注的示意。

## 1. 工作台首页

- **目标**：恢复上次工作、处理待审批和失败，不制造与业务无关的统计大屏。
- **流程**：最近项目/流程 → 继续编辑；待处理事项 → 精确进入运行节点；首次使用 → 创建项目 → 创建流程。
- **布局与组件**：左导航208px；页头问候省略，直接“工作台”；最近项目横向简洁入口；待处理事项表；最近流程与最近运行上下排列。汇总仅“项目 / 工作流 / 待审批”三个小数字。
- **状态**：初载骨架、无数据欢迎、局部请求失败、服务离线；待审批数量来自服务，不从节点颜色推算。
- **数据来源**：项目/工作流列表、非终态运行、待审批聚合查询；工作台聚合接口可以复用领域查询，不新建统计数据库。
- **空态/异常**：无项目显示创建向导和离线示例说明；没有待处理事项显示“当前没有待审批运行”；服务断开保留最近读到的数据并加“可能过期”。
- **关联**：链接项目、编辑器、运行；进入状态由对象ID定位，不依赖列表顺序。

## 2. 项目管理

- **目标/流程**：搜索项目 → 创建/编辑基本信息 → 进入工作流；名称必填1–80字、描述最多500字；前端与后端使用同一约束。
- **布局/组件**：标题和新建按钮、搜索框、表格（名称/描述摘要/流程数/更新日期/操作）。新建/编辑用同一360–480px对话框。
- **状态/数据**：query保留搜索与游标；mutation提交中禁重复；成功失效相应列表缓存。数据来自 Project，流程数为查询聚合。
- **异常/空态**：无项目可新建，无搜索结果可清空筛选；同名可允许但建议提醒；请求失败保留输入。删除是软删除，说明其工作流不再出现在正常列表中；存在非终态运行时阻止删除并给运行链接。
- **关联**：项目行进入工作流；操作菜单避免整行点击误触。恢复软删除项目列为P1，不暗示P0有回收站。

## 3. 工作流管理

- **目标/流程**：在项目中找到流程 → 查看草稿/发布版本/最近运行 → 继续编辑或查看历史。
- **布局/组件**：项目面包屑、名称/说明、搜索、新建；表格列为流程名、草稿更新时间、最新发布版本、规格状态、最近运行、操作。草稿有变化时标记“未发布修改”，不能只显示绿色“已发布”。
- **状态/数据**：Workflow + draft revision + latestVersion + 最近WorkflowRun；列表不加载完整definition或日志。
- **空态/异常**：没有流程提供空白流程和内置离线验收示例；发布版本缺失时显示“未发布”，历史为空可进入编辑试运行。
- **关联**：编辑、规格、历史三个明确入口；“运行发布版本”先选输入并显示版本；新建进入规格引导，可跳回画布补充，发布前再完整校验。
- **删除**：软删除确认展示名字和历史保留说明；非终态运行阻止删除。复制流程为P1，不与P0画布节点复制混淆。

## 4. 可视化工作流编辑器

- **目标/流程**：选择节点 → 配置输入输出 → 连线 → 校验 → 保存/发布/试运行；规格和任务关联可随时侧栏查看。
- **布局/组件**：专注导航、顶部流程上下文、节点库、React Flow画布、属性面板、底部工具条、问题抽屉；详见 [编辑器专规](WORKFLOW_EDITOR_DESIGN.md)。
- **状态**：加载/编辑/保存中/已保存/保存失败/版本冲突/只读历史；草稿与版本状态使用不同徽标。初始自动保存防抖800ms；Ctrl+S立即保存。
- **数据来源**：WorkflowDraft聚合快照、NodeDefinition元数据、静态校验报告；节点运行状态不写入草稿。
- **空态/异常**：新建预置Start/End并说明如何添加任务，不自动生成虚假业务；错误边和问题清单双向定位；未知节点类型显示可读占位并阻止发布，不删除用户配置。
- **关联**：规格任务面板、发布对话框、试运行输入抽屉、独立运行路由；编辑过程中查看历史不覆盖当前草稿。

## 5. 任务规格与配置

- **目标**：把业务目标与可验证执行对应起来；人工拆解，不依赖在线模型。
- **流程**：规格七字段 → 输入/输出schema编辑 → 新建任务 → 职责/依赖/完成条件 → 关联画布节点 → 创建测试案例。
- **布局/组件**：页头流程名/保存状态；“规格 / 任务拆解 / 测试用例”三个页签。规格为分节表单；任务为可排序表格+右侧详情；依赖为多选列表，关联节点可检索。
- **约束**：一个工作流一个规格；一个任务可映射多个节点，节点至多关联一个任务。任务依赖需能由控制图路径解释；只在任务表填依赖不会自动生成隐形连线。验收标准可同时保留说明文字和结构化断言。
- **状态/数据**：TaskSpecification、TaskItem、TestCase；规格、任务、定义/layout共用draft revision。页面切换前保存未提交字段；保存失败保留编辑。
- **异常/空态**：无任务可手工新增；删除被节点引用的任务需先展示关联节点并显式解除；依赖成环定位任务行。输入schema不合法时保留原文本并阻止保存，不偷换为任意JSON。
- **关联**：任务行“定位节点”打开画布；从节点面板返回关联任务；测试结果进入真实运行记录与断言差异。

## 6. 工作流执行监控

- **目标**：知道当前运行到哪里、等待什么、为什么失败，以及是否需要人工介入。
- **流程**：创建运行返回runId → 获取快照与事件游标 → SSE订阅 → 选节点看本次尝试/输入输出 → 审批或取消 → 查看最终断言。
- **布局/组件**：页头运行号、来源（草稿测试/发布vN）、状态、开始时间、耗时、取消；中央只读版本画布；右侧节点概览/尝试/输入输出/日志；底部事件时间线。队列和并发信息只显示能帮助解释等待的内容。
- **状态/数据**：WorkflowRun快照 + NodeRun/NodeAttempt + ExecutionEvent + ApprovalRequest + TestResult。状态完全由后端事件/快照驱动，计时器只更新“已过时间”，不得推导完成状态。
- **审批**：展示待确认摘要、输入、截止时间；批准/拒绝需简短理由（拒绝必填）；提交中禁重复，竞争提交返回409时重新读取决定。拒绝会导致运行失败，须在操作旁说明。
- **异常/空态**：断线黄条“连接中断，后端可能仍在执行”；重连按seq补发。运行INTERRUPTED显示已完成记录及“基于此快照重新运行”；重跑是新runId，不能叫“恢复”。已取消不保证外部效果回滚。
- **关联**：回到对应快照、原草稿、历史；运行结束画布不自动消失。首版没有任意时刻暂停按钮。

## 7. 执行历史与日志详情

- **目标/流程**：筛选范围 → 找运行 → 查失败节点/尝试 → 对照预期/实际 → 基于同一快照复现。
- **布局/组件**：项目/工作流/状态/时间筛选；运行列表含来源、状态、耗时、错误摘要；选中右侧详情摘要，点击“打开运行”使用监控页同一只读组件。日志按节点、等级筛选，游标加载。
- **状态/数据**：持久化WorkflowRun、NodeRun、NodeAttempt、ExecutionEvent与TestResult；服务重启后仍可读。列表分页不一次加载全部事件。
- **异常/空态**：没有历史提供试运行入口；筛选无结果可重置；已清理记录显示“记录已按保留策略清理”，不能伪装网络失败。JSON预览截断明确说明，不隐藏输出错误。
- **验证视图**：每个断言显示规则、JSON路径、期望、实际、通过/失败；文本比对逐行，JSON字段差异按路径列；没有测试用例时说明“本次未附加测试断言”，不等价于验收通过。
- **关联**：原快照只读；“再次运行”先展示新运行输入与副作用提示。P0没有从失败节点接着跑或修改旧结果功能。

## 8. 应用设置

- **目标/流程**：查看本地服务/数据目录 → 配置日志保留 → 创建备份 → 查看诊断信息。
- **布局/组件**：分节列表“本地运行 / 存储与保留 / 备份 / 关于与诊断”；不做云账户、订阅、团队权限设置。
- **数据来源**：AppSetting、服务health/info、磁盘用量摘要、备份作业结果；数据目录只能按启动配置改变，界面展示路径和重启说明，不随意移动正在使用的数据库。
- **交互状态**：备份中显示具体状态，完成提供路径/结果；清理前列预计删除记录范围，只清理符合策略的终态数据；有运行时禁止恢复备份。
- **异常/空态**：磁盘不足/只读目录/备份失败展示错误与可执行建议；初次无备份提示先创建。诊断只显示版本、路径和脱敏错误，不展示密钥。
- **关联**：异常详情可回运行日志；本地恢复建议采用停止服务的命令流程，P0设置页提供流程说明，不提供未经实现的热恢复按钮。

## 9. 横切文案与反馈

“已保存”=后端已提交当前revision；“已发布”=生成不可变版本；“执行成功”=运行终态满足引擎条件；“测试通过”=本次测试断言全部通过；“等待审批”不等于可暂停一切任务。所有错误至少包含可读原因、关联对象、建议下一步和可复制requestId；只在技术详情展开内部错误代码，普通用户流程不暴露堆栈。
