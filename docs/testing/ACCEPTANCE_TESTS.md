# 通用验收标准
下表为课堂闭环验收。浏览器前端回归覆盖的子集见文末；正式版本、真实模型与后端验收记录在对应服务实现后补齐。

| 编号 / 优先级 | 操作 | 通过条件 |
|---|---|---|
| A01 P0 | 创建两个独立项目，保存/读取各自规格 | 数据不串用，错误项目引用被拒绝 |
| A02 P0 | 输入合法规格，导出/导入JSON；修改一字段另存 | 内容规范化后相同；新旧版本可独立读取 |
| A03 P0 | 删除必填、重复需求ID、输入关键矛盾 | 结构错误在模型调用前阻断；语义不确定不静默编造 |
| A04 P0 | 对用户提供的规格发起REAL规划 | 记录真实Provider调用、规格版本与结构化候选；不能返回固定表 |
| A05 P0 | 检查每项任务的交付、验收、角色、需求引用 | 类型/引用正确，must需求有实质覆盖且人工通过 |
| A06 P0 | 注入重复ID、缺失依赖、自环、环、错误成果引用 | 全部拒绝正式保存，返回准确位置和修复建议 |
| A07 P0 | 对抽象分叉汇合图编排；改变坐标再次编排 | 汇合排在所有父节点之后，同层无依赖；坐标不影响结果 |
| A08 P0 | 列表选任务、画布选节点、打开详情 | task_id一致，依赖/交付一致，未执行节点无成功运行状态 |
| A09 P0 | 改任务依赖并保存；并发提交旧expected_revision | 新版重算，旧版不变；冲突409且不丢本地编辑 |
| A10 P0 | 保存后重启、断网看历史并导出 | 不调用模型即可读取；业务hash/TEST来源保留 |
| A11 P0 | 改变实际规格的需求、约束或粒度后重规划 | 相关任务内容/交付/依赖有合理变化，无产品名分支 |
| A12 P0 | 注入超时、401、空白、截断和预算耗尽 | 有界失败、诊断完整、无自动TEST降级或重复无限收费 |
| A13 P1 | 撤销拖动/依赖编辑/布局，再重做 | 草稿可逆，服务器历史不被撤销 |
| A14 P1 | 修改可选规划约束并读取旧计划 | 新约束影响新请求；旧快照和历史保持不变 |
| A15 P2 | 执行批准的冻结计划并检查交接 | 真实产物hash及输入manifest对应，非仅模拟状态 |
| A16 P2 | 审批拒绝、取消、迟到结果、审查失败与修订 | 终态一致；修订新PlanRevision/Run，证据可追踪 |
| A17 P2 | 文档解析后遗漏必要信息 | 明确缺失且须用户确认，不能直接形成正式计划 |

门槛：所有P0结构检查通过、must语义评审通过、无阻断缺陷；质量属性中的P0目标有测量记录。

## 浏览器前端的当前回归

| 范围 | 当前通过条件 | 正式验收边界 |
|---|---|---|
| A01–A03 的前端子集 | 创建项目；编辑并往返导入导出规格；拒绝格式错误、坏编码和重复 JSON 键。 | 项目引用隔离的 API 验收及不可变 SpecRevision 仍需后端。 |
| A05–A07 的前端子集 | 官方样例批次一致；必需需求缺覆盖、关键或重复假设阻断；可选覆盖缺口告警；边数 1,000 的边界通过。 | 正式报告、策略与实质覆盖由服务端和人工复核。 |
| A08 与本地历史 | 列表/详情/画布的任务一致；拖动时节点和连线可见；注释不参与布局；保存后坐标与历史可恢复，PNG 可导出。 | A09/A10 的正式版本、CAS、业务 hash 和 ExportBundle 另行验收。 |

测试入口、基准提交及证据见[实现审计](../PROJECT_AUDIT.md)。
