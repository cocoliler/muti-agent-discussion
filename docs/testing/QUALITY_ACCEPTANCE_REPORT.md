## 说明

- Q02 的 100 次测量中 50 次为合法稠密 DAG，50 次为同规模的环图；非法输入必须返回空派生结果和明确错误。
- Q03 的事务失败通过运行时注入 `Session.commit` 异常完成；响应为 500，保存前后均为 100 个版本，证明没有新增部分数据。
- Q04 使用生产构建和真实 React Flow 画布。每次拖动持续 10 秒，以 `requestAnimationFrame` 计数；记录长任务次数和首屏可交互时间。
- Q05 的进程重启来自 P0 HTTP 验收：停止服务后用同一 SQLite 数据目录重新启动，再比较规格、计划、布局和导出 hash。
- Q06 的真实时延来自用户规格的 REAL 验收；虚拟故障覆盖 401、超时、空白、截断、预算和重试边界。
- Q07 的密钥扫描只输出命中数量，不输出密钥。非法 Host/Origin 和敏感回显由后端测试覆盖。
- Q08 使用 Tab 序列和 Enter 打开任务详情验证键盘核心路径；对比度覆盖浅色和深色主题的主要文字/背景组合。

## 限制

1. 性能只在上述单台 Windows 机器和 headless Chrome 上测量，不能外推为所有客户端或硬件组合。
2. Q04 拖动由 CDP 以约 10Hz 指针事件驱动，帧率用页面 rAF 统计；应在有界面环境下复测主观流畅度。
3. 成功 `PlanningRun` 响应仍不暴露 Provider request ID；REAL 证据使用 run ID、attempt、usage、候选和报告。
4. Q08 的 P1 键盘验收覆盖核心导航和详情入口，不等同于全部字段编辑流程的人工可用性认证。
5. `npm audit` 报告 4 个 high 漏洞，均来自 Vite 开发工具依赖链；`npm audit --omit=dev` 为 0。不得用会导致 Vite 主版本降级的 `--force` 修复，后续单独评估升级。
