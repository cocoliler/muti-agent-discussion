# 交互设计对照
证据和访问范围统一见 [参考研究](REFERENCE_PROJECTS.md)，下表为本项目设计推论。

| 场景 | 可借鉴模式 | FlowStudio 决策 | 不直接采用的原因 |
|---|---|---|---|
| 复杂画布 | Dify 主画布与侧面配置 | 右侧360px详情，默认收起，规格抽屉按需出现 | 任务交付/需求覆盖比模型温度更重要 |
| 节点连接 | n8n 清晰端点和关系 | 左输入右输出、箭头、文本错误、快捷键替代 | 不能把屏幕位置当执行顺序 |
| 动态配置 | Flowise 元数据驱动属性 | 固定任务字段+可选约束；不支持任意脚本表单 | 类型安全和可维护性优先 |
| 图编辑 | React Flow 自定义渲染 | Task/Stage/Note 三类展示，只有Task有业务依赖 | 阶段和注释不是可执行任务 |
| 调试历史 | 工作流产品的运行历史 | 当前展示“规划历史”；未来另设“执行记录” | 避免把模型规划成功当软件开发完成 |
| Agent过程 | MetaGPT角色与中间成果 | 规格→任务→计划→未来产物均有契约 | 不强制重新写PRD或整套角色链 |

默认不用复杂后台左侧多级菜单、不展示无实现的运行按钮。首屏保留项目名、规格摘要、版本、主操作和画布。
设计模式支持编辑；查看模式冻结业务并允许缩放、平移和详情；历史编辑通过复制形成候选。
